# 架构与所有权

语言：[English](../../core/architecture.md) | 简体中文

## 物理层级与逻辑层级一致

公开模块位于 `ui/`。组合层次是 `core → base → kit`，分别对应平台原子能力、Base UI 式行为和默认组件外观。依赖向下：`kit` 组合 `base`，`base` 使用 `core`，core 包不导入组件。可选渲染器和宿主位于 `extensions/`，消费更低层合同。

| 目录 | 职责 |
| --- | --- |
| `ui/core/scene` | 挂载、焦点、事件路由、帧投影、语义观察和类型化动作 |
| `ui/core/text` | 安全文本、显示宽度、逻辑位置与布局投影 |
| `ui/core/program` | UI 执行序列、作用域资源、传输合成和会话生命周期 |
| `ui/core/publication` | 不可变永久内容的准入、有界待发责任和回执 |
| `ui/base` | 组合 scene 原子能力的交互与内容策略 |
| `ui/kit` | 基于 base 行为的外观和常用复合组件 |
| `ui/automation` | 在所有者序列上观察、定位、调用和条件等待 |
| `ui/uitest` | 进程内宿主测试和真实终端一致性辅助 |
| `extensions/` | 可选解析器、渲染器和宿主依赖边界 |

包依赖图依据 Go 实际导入检查。注释提及上层消费者不构成代码依赖；文档导航可以解释下层原子能力如何被组合。

## 每个事实只有一个可推进所有者

| 事实 | 所有者 | 只读或派生表示 |
| --- | --- | --- |
| 实际挂载与挂载代次 | `scene.Root` 及场景节点 | `Element`、`Attachment`、`Target` 句柄 |
| 键盘焦点与指针捕获 | `scene.Root` | 语义焦点标记和事件目标 |
| 字段值 | 具体 base 控制器或显式领域 Control | 表单输出、语义值、kit 绘制 |
| 可编辑逻辑文本与修订 | `base.EditSession` | 编辑器布局，以及通过变更映射的光标和选区 |
| 流式源与最终化 | `content.StreamDocument` | 不可变源快照与准备结果 |
| 保留的会话内容引用 | `base.Transcript` | Transcript 布局与阅读锚点 |
| 永久输出责任 | `publication.Publisher` | 不可变批次和并发安全回执 |
| 工作线程结果 | `program.Task` | 任务状态；取消请求和结果交付是独立字段 |
| 终端实际写入进度 | 帧写入器 | 发布与场景的 written 水位投影 |
| 应用调色板 | `kit.ThemeOwner` | 不可变主题 scope 和解析后的实例调色板 |

既读取应用状态、又持有独立可写本地值的访问器，不是受控组件合同。自有字段通过唯一控制器和类型化领域操作推进。`ConfirmControl` 这类显式受控协议将 Snapshot、带预期版本的 Change 与 Subscribe 委托给领域所有者，不保留第二份可写答案。皮肤持有控制器，不复制值、选区、焦点或路由策略。

## 模型、布局与写入进度不同

输入或类型化动作推进模型。`Root.Prepare` 将几何暂存为不可变帧投影；终端编码器准备字节，但不推进差分基线。写入器准入后，完整场景与输出候选一起提交；物理写入完成随后推进 written 水位。

中止候选保留此前完整几何与终端基线，但不回滚已经接受的模型变更。指针事件使用与到达时刻关联的帧几何，也包括 `scene.Snapshot` 保存的局部投影。缩放使不再匹配的几何失效；卸载目标永远不能指向其替代者。

## 组合只有一种实际结构机制

`scene.Group` 和 `scene.Overlay` 拥有实际子节点挂载。Base 选择行为并装配这些原子能力；kit 填入外观槽，或围绕相同行为部件组合更多原子能力。焦点和自动化不各自维护另一棵可写组件树。

`scene.Action[P, R]` 拥有可用性、参数验证和调用结果。键盘、指针与自动化复用该动作或相同的类型化所有者操作。禁用、只读、忙碌和模态约束对语义调用同样成立。

## 预算必须对应具体阶段

源字节、准备后的单元格、键元数据、每次测量工作、已接受任务资源、发布存储和编码后写入载荷，是不同的预算，各自由其所有者执行。有界视口本身不能证明解析、保留历史或排队输出有界。

完整 Markdown 准备保留有界的全部源，因为后来的引用可能改变前文含义。`VirtualWindow` 限制实例化和测量缓存，但键索引与估算行偏移的遍历仍取决于配置的数据集规模。仅有单元格差分不能推出端到端性能优势。
