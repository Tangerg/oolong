# 资源与发布生命周期

语言：[English](../../core/lifetimes.md) | 简体中文

## 作用域工作

UI 所有者通过 `Runtime.NewScope` 创建 `Scope`。`ScopeConfig.Attachment` 可将交付资格绑定到一个挂载代次，`Context` 增加外部生命周期。`Runtime.Start(scope, Work[T]{Run, Apply})` 在启动 `Run` 前预留完成容量。工作线程返回类型化结果；只有作用域仍具资格时，`Apply` 才在 UI 所有者上执行。

`TaskStatus` 将工作线程结果、`CancelRequested` 与结果交付分开。调用 `Cancel` 是请求协作，不能声称外部工作已经结束。视图卸载后，即使工作成功，UI 交付也可能被撤销。`Task.Done` 和 `Task.Settled` 暴露不同边界。普通 dispatcher 拥塞不会丢弃已接受任务的完成结果。

## 已接纳的帧与指针输入

自定义合成器在写端水位推进时调用 `Root.Wrote(sequence)`。若有多次接纳等待确认，水位选中它实际覆盖的最新布局，之后的接纳继续等待；一个确认不会为中间帧编造显示时间。`RootConfig.MaxPendingFrames` 独立限制待确认的布局数量，默认八个。容量满时 `Prepare` 返回 `scene.ErrBusy`；等确认后再准备下一帧。窗口大小变化或几何失效后，旧坐标和语义节点的旧边界不再有效。

指针输入绑定挂载、内容标识、内容修订和坐标帧。回调中途换掉这些事实，同一次点击不能落到替换内容上。在当前弹窗内安装它允许执行的快捷键；通过可选的 `DialogConfig.Dismissed` 结算实际关闭后的业务，无论关闭来自键盘还是代理调用。

## 移动一个已挂载的元素

移除元素时，附件的 `Done` 立即关闭。旧挂载上的失焦、取消捕获或移除回调仍可能在排队或执行。若重新挂载返回 `scene.ErrCleanupPending`，请先让旧回调返回，再由旧根的所有者结清通知，然后重试。无关联的元素可以立即挂载。回调异常中断后，未交付的通知保持顺序；嵌套结清不能插队。关闭根会唤醒当前及之后订阅变化的调用者。

可以保留事件用于读取输入。用事件改变焦点或捕获指针的权限随回调结束或更新的输入轮次而失效；要在以后发起命令，请保留元素或可检查挂载代次的目标。

## 永久发布

`Publisher.TryPublish` 在接受责任前，将完整 drawable 捕获为不可变、自有的单元格。原生 painter 被拒绝，因为其生命周期需要活动帧所有权。捕获失败、不支持的输出与容量拒绝，都将责任保留给调用方。空捕获内容获得 sequence 为零的 written 空操作回执。

| 回执状态 | 含义 |
| --- | --- |
| `Accepted` | 发布器拥有不可变内容，但可能仍未进入写入器 |
| `Written` | 物理写入水位已覆盖对应 sequence，或贡献本身为空 |
| `Failed` | 责任因已知失败而结束 |
| `UnknownPartial` | 已进入写入器的字节可能部分到达目的地 |

发布 ID 标识已接受责任，不替代传输 sequence。待合成与已进入写入器的捕获共享 item 和字节预算，经过一个缓慢队列不会提前释放该预算。

## 组合的只读借用

`Element.ReadOnly` 同步执行投影，期间由组合的阶段所有者拒绝模型与挂载关系的变更。已挂载组合使用场景根；尚未挂载的组合使用最外层 Group 或 Element。借用期间禁止挂载或移动组合，因此回调无法切换到另一个所有者来绕过检查。嵌套借用会恢复外层阶段，panic 或 goroutine 退出也遵循同样的释放规则。

Transcript 在发布捕获时复用这个原子能力。它的滚动、选择与 sticky 控制器已经共享同一个 Element，因此各自的命令都查询同一个阶段所有者，不再维护额外的捕获标志。`Element.Measure` 同样复用该边界。这是 UI 所有者顺序上的合同，不能据此从工作线程并发调用 UI 操作。

控制器的绘制和 staging 必须使用挂载其真实 Element 的 Root 所提供的帧。自定义控件在计算候选几何或调用渲染回调前，调用 `Element.CheckProjection(frame)`。应挂载这个 Element，并在挂载前填充它的 paint slot；另一层无关包装不能成为第二个几何生产者。尚未挂载的控制器仍支持模型操作与测量，但不能提交几何。没有关联 Element 的独立原子能力遵循其帧的阶段。

只读借用也拒绝 snapshot 的 staging 与 refinement。一个候选必须先 commit 或 abort，才能开始新的只读借用或测量。这样，之前保存的候选就不能在回调内部改变正在观察的几何，同时 Commit 仍可以结算已接纳输出，不增加一个新的拒绝点。

`ScrollLayout` 只在产生它的绘制回调内读取和细化同一个 staged candidate，不保留可以独立推进的 offset 副本。细化被拒绝时，候选值及可读 offset 都保持不变；准备结束后，通过 `Scroll.Offset` 读取控制器当前的位置。

## 原子输出与关闭

`Publisher.Prepare` 读取不可变待发前缀。`grid.Inline.Prepare` 将它与活动帧一起合成，但不推进锚点。运行时验证完整编码载荷与写入器容量，再连续提交发布、输出和场景候选，中间不运行应用回调。拒绝时中止候选，之前的完整投影继续有效。

`CloseAdmission` 停止新发布，同时保留已接受内容用于最后一帧和排空。`Written` 结算真实进度。终端失败以实际原因结算剩余责任。延迟的 `FlushNotifications` 在全部所有者结算之后执行，使 Transcript 在后续所有者轮次恢复被容量阻塞的发布。

Inline 关闭时先等待最后一帧写完，再接纳光标清理，并等待清理本身完成。因此，即使写入器只允许一个普通帧，也能保持输出顺序与光标恢复，不依赖后台写入线程恰好先获得调度。

## 独立资源预算

StreamDocument 限制保留源字节；Capture 限制单元格与自有字符串；Publisher 限制完整保留捕获。运行时限制动作与资源准入，写入器限制编码字节与待写传输。这些数量不会被拼成虚构的通用内存数字；自定义渲染器内部的调用方分配仍由调用方负责。

应用通过 `runtime.Publisher()` 获取生产者句柄。每次 `TryPublish` 都检查当前会话和写入器，保存下来的句柄也遵循这个规则。接纳成功会请求绘制；只有 compositor 可以设置几何、接纳写入序列或结算回执。自建 compositor 时，才自行构造并拥有 `publication.Publisher`。

## 回调权限

场景将单元格和暂存几何的写权限交给一次绘制回调。回调一旦返回，它保存的 frame、副视图、普通 grid 视图及暂存句柄就全部失效；嵌套的只读操作也不能通过它们写入。合成器仍拥有底层目标，开始绘制兄弟组件不会让旧画笔重新有效。自定义布局返回后可以复用矩形切片。

直接编码终端输出的 painter 在 `Paint` 和 `Erase` 中接收 `grid.PaintContext`。它实现 `io.Writer`，并提供不可变的单元格尺寸与原生图层。副本共享一次回调的借用期，过期写入返回 `io.ErrClosedPipe`。由于不透明输出无法更新单元格编码器的样式缓存，合成器在每次回调前后都关闭超链接并重置 SGR。原生图片在文字下方按组合顺序分层，上传 ID 不参与排序；低层 Kitty 编码必须显式接收该图层。

在预览或冒泡阶段使用指针命令，既检查原命中内容，也检查实际接收节点。认领按下会停止传播；拖动与松开必须具有到达时的布局，且仍属于认领时的内容，证据失效就取消手势。清理通知不能认领新手势。无可聚焦子项的弹窗可自行接收按键，无须虚构焦点。非指针输入的 `Event.Read` 从本场景当前布局读取；缺少投影与明确暂存 nil 是两种结果。

## 交出终端或使用图片资源

终端所有者先暂停普通帧接纳，再排空已有输出并交出显示权。已保留的帧写端不能切换到控制队列或关闭 writer；成功取回终端后，普通写入才能继续。环境查询在取得 raw mode 前完成。

`Session.Suspend` 先按这个协议交出终端，再调用 `term.Suspend`。Linux、Darwin 和 FreeBSD 的停止请求必须经过操作系统的同步边界，调用才能返回。默认作业控制会在继续后返回；忽略信号、宿主自定义处理和孤立进程组可能使进程继续运行。停止信号被阻塞或平台不支持时，返回 `errors.ErrUnsupported`，不排队一个可能迟到的停止请求。库不替换宿主信号策略，也不等待一个可能永远不会出现的继续信号。

支持原生图片的宿主用自己的 `graphics.ImageOwner` 绑定已接纳的传输，同时提供该所有者的 `NativeTarget`。资源句柄带有签发目标和传输寿命。先停止绘制，再通过同一宿主释放。即使两台终端各自使用了相同的线协议编号，也不能将活资源放到另一台终端。低层 `graphics.Image` 用于显式协议编码，其数字 ID 不是资源回执。
