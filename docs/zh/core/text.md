# 逻辑文本与单元格投影

语言：[English](../../core/text.md) | 简体中文

## 位置属于文档修订

`text.Position` 表示逻辑行、UTF-8 字节偏移与亲和性，只在某个文档修订内有意义。`text.Layout` 拥有规范化、单元格命中、光标、矩形和渲染行映射。`LayoutConfig.Lines` 接受 `[]text.Line`；普通字符串用 `text.Of(value, style)` 包装，已有投影继续保留为 Line。字节偏移属于已接纳的逻辑文本，不声称对应原始 Markdown 或终端转义序列。

单元格是显示原子的投影。原子的跨度由 grid 拥有，可以超过两列。裁剪、覆盖、选区修饰与编码保留原子边界。渲染器不能根据字节长度推导宽度，也不能将原子尾部单元格视为独立字符。

`grid.ClusterWidth` 是唯一的列宽依据。歧义宽度字符占一列；emoji 呈现序列（符号后接 VARIATION SELECTOR-16，例如 `⚠️`）占两列，与当前终端和复用器的绘制方式一致。控制字符不会进入单元格。删除控制字符后留下的零宽修饰符，如果会附着到前一个可见字素，也会被丢弃。

`text.Line` 先过滤控制字符和无效 UTF-8，再划分显示字素。绘制、列宽、折行、截断和高亮共同使用这一组原子。删除分隔字节可能使可见字节合并，例如区域指示符配对和 emoji 连接符序列。第一个保留的源字节决定完整原子的样式与超链接。`Wrapped.From`/`To`、`Line.ColumnOf`、`Line.OffsetAt` 和高亮匹配仍指向原始源字节。包级 `text.Clusters(string)` 划分未经修改的字符串，无法恢复 Line 的显式边界。合并后显示原子内部的偏移没有独立单元格位置。

每次 `Line.Draw` 都拥有自身几何。独立的零宽字素不占单元格，不能修改左侧已有画布原子或制表符留下的未绘制间隙。如需让独立修饰符拥有可见的空格基底，先用 `Pad(0, layout.Start)` 准备字段。低层 `View.Text` 继续保留下文所述的显式组合行为。

`Span.BreakBefore` 保存普通字符串无法表达的显式字素边界。它不创建新行，不重置 tab stops，也不取代样式或链接的归属。普通源 span 保持 false，让字素内部的样式变化不会拆开字素。物化后的显示原子保留必要边界，使 tab 展开的空格与后续修饰符保持独立，包括占有正列宽的修饰符；不另存一份需要同步的宽度表。

使用 `Line.Display` 获取过滤后的显示内容，同时保留 tab 和显式边界。`Line.String` 为复制或匹配序列化文字，不序列化几何。测量、绘制、`Clusters`、字节与列转换以及布局继续读取 Line；从字符串重建 Line 可能让原本独立的原子合并。`Line.Clusters` 提供源区间的两个端点，因为过滤字节后，显示字素的字节长度可能短于原始区间。

`line.Fill(width)` 重复图案的显示原子，并用空格补齐剩余列。没有可绘制宽度的图案只产生空格，非正宽度产生空行。Markdown 与 LaTeX 组合这一能力，不另设列宽规则。原有返回字符串的包级 `Fill` 和 `Truncate` 函数已移除；用 `Of` 构建 Line，并在格式处理与绘制过程中保留该投影。

`line.Pad(width, alignment)` 使用 `layout.Start`、`Center` 或 `End` 准备独立对齐的字段。它从字段原点展开制表符，并为会吸收相邻补白的边缘字素补上自己的空格基底。基底保留内容的样式与链接，额外补白使用默认外观且不带链接。补齐边缘可能增加自然宽度，因此先用 `Pad(0, layout.Start)` 准备字段，再测量或折行。补白不会截断过宽字段。拼接独立字段时保留显式空格分隔；任意字段字节直接拼接不能保留全部字素边界。

## 有列宽预算的后缀组合

`line.Truncate(width, suffix)` 只在正文超过预算时添加后缀。`line.WithSuffix(width, suffix)` 总是包含可绘制后缀，必要时沿完整字素边界缩短后缀和正文。限制行数的 Paragraph 使用后者，因为即使最后可见行本身放得下，后续隐藏行仍需要标记。

后缀和保留正文必须保持独立字素边界。因此，只含 VARIATION SELECTOR-16 等连接修饰符的后缀会单独保留，不改变前一个符号的宽度或超链接。正文制表符按原始列位置展开，后缀制表符从保留前缀的位置继续推进。后缀继承最后保留字素的样式；没有前缀时使用默认样式，始终不继承超链接。

## 单元格原子的编码

即使相邻 Unicode 字节会组成肤色修饰、零宽连接符序列、区域指示符对或间距附加符，独立的 `View.Text` 绘制仍保留各自的单元格坐标。公共终端编码器只在分段会跨越原子边界时插入相对光标往返，保持最终位置不变。完整帧、差异帧、Inline 行与冻结发布共用此规则；样式和超链接变化不能作为字素边界。

零宽扩展通过普通文字共用的几何写入路径并入左侧原子，保留其样式与链接，重新计算整体宽度与尾部单元格，并对完整结果执行裁剪。`View.Text` 返回的列增量包含左侧原子宽度的变化。

调用方在写入 `EncodeRow` 输出前定位光标，结束此前的字素，并确保整行能放入该列至终端右边界之间。编码可能包含这些相对光标边界，但不会依赖绝对屏幕行。`Surface.Rows` 的普通字符串只携带文字，不携带终端几何；拼接其字节不能保留独立原子的边界。

`EncodeRow` 在输出单元格前恢复默认 SGR 样式，并关闭继承的 OSC 8 超链接；整行结束后仍保留这些默认状态，空行也一样。因此，此前无关的输出不会改变本行外观，也不会把超链接泄露到后续文字。

## 编辑器与会话组合共享映射

`base.EditSession` 拥有可编辑文本、变更与修订映射。多个编辑器可以查看同一文档，不成为额外文本所有者。选区与光标依据文档变更映射；宽度改变只重建视觉投影。

`text.IsClusterBoundary(source, byteOffset)` 在完整字符串上检查字素边界。比较拼接前后的字素数量并不足够：区域指示符可以改变配对，却保持总数不变。原子元素插入和重复密码掩码都在发布文档变化前检查实际拼接边界。

`LayoutConfig.ReserveCaret` 为末行填满宽度的已折行逻辑行保留插入续行。光标、命中、选区与行数测量共用该投影；向后亲和性也不能将插入光标放到分配列宽之外。该选项默认关闭，不折行布局忽略它，因此被动文字不会额外增加尾行。

`text.Row.Content` 保存实际绘制的 Line，`SourceLine` 是可选的、从一开始计数的逻辑源行号。`Offset` 将装饰排除在可复制内容之外，同时保留内容的位置。生产者和留存快照复制自有 Line 存储，不暴露内部可写的 span 切片。

Transcript 端点额外包含 `BlockID`、准备后的内容修订和逻辑投影指纹。`text.Row.Joined` 与 `Gap` 的软折行元数据重建可复制逻辑文本，并保留有效原子边界。指纹忽略外观，但会区分字节相同、原子几何不同的内容。如果宽度相关渲染器改变了逻辑投影，旧选区将返回 `ErrStaleSelection`；库不会编造并不存在的源映射。

## 阅读与复制

`Transcript.Layout().Hit` 将显示单元格转换为逻辑端点。`Selection.Text(layout)` 从该投影读取可打印文本，`Selection.Rects(layout)` 将高亮投回单元格。选中修订不可用时两者都会拒绝。未知非文本内容保留物理行位置，但不伪造复制文本。

阅读锚点是内容身份、逻辑位置、视口偏移与 scroll 所有者跟随末尾意图的投影。重排据此推导新偏移，锚点不会独立推进滚动状态。固定标题与正文使用同一份候选内容映射。

编辑器将实际改动的字节区间交给会话。即使相邻文字相同，编辑位置也不会被重新推测；撤销和重做分别使用反向和正向区间。共享密码掩码约束所有写入路径，包括 Reset，并让所有视图的语义值都脱敏。每个视图仍独立拥有自己的光标、选择和滚动位置。

## 解码有界命令输出

`text.Decoder` 保留尚未结束的逻辑行、样式状态与不完整转义。其零值和 `text.Decode` 不限制逻辑行接纳。接入不可信或长期运行输出时，应用可使用 `text.NewDecoder(text.DecoderConfig{MaxLineBytes: ..., MaxLineSpans: ...})`。负限额会被拒绝；零值关闭对应限额。`Base` 仍为后续文字提供默认样式，改变它不会重写已接受的 span。

解码器独自核算所持有的逻辑行。字节预算包括规范化后的可打印 UTF-8、每个 span 的链接目标，以及尚未由最后一个 span 表示的活动目标。同一目标出现在多个 span 时逐个计入。span 预算计算已解析的样式/链接片段；相邻且相同的片段跨读取边界合并。OSC 8 目标在留存前验证，即使尚无可见文字。转义 framing 自有固定 scanner 限额。CR 和其他被丢弃的控制字符既不创建 span，也不重置逻辑行预算；完成的换行才会转交该行。

`Feed` 和 `Flush` 均返回 `([]text.Line, error)`。处理 `Feed` 的错误前，仍要处理它返回的完成行：同一次读取中，已接受的完成前缀可以出现在超限行之前。接纳检查先于超限数据的留存。首次拒绝返回可由 `errors.Is(err, text.ErrLineLimit)` 识别的错误，将已接受的 UTF-8 前缀保留在 `Open`，丢弃剩余输入，并让后续 `Feed` 持续返回该失败，直到 `Reset`。

到达 EOF 时，`Flush` 按相同的替换与接纳政策处理不完整 UTF-8，丢弃不完整转义。成功刷新只转交最后一行一次；拒绝则让前缀继续可经 `Open` 读取，返回错误而不把失败行作为完成行转交。反复刷新不能清掉错误或可见前缀。`Reset` 丢弃流状态与失败，保留配置限额和当前 `Base`。

解码器预算与 publisher 预算保护不同的所有者：前者限制仍可修订的输出，后者限制已被接纳为永久输出的完成内容。源因接纳失败被取消时，应用仍应在自身生命周期内排空已接受的完成行，不能让源取消同时撤销这份责任。
