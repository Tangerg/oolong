# 渲染富内容

语言：[English](../../guides/content.md) | 简体中文

## 显式选择语法

运行 `go run ./examples/content`；[内容示例](https://github.com/Tangerg/oolong/tree/main/examples/content) 组合独立的 Markdown、高亮和数学渲染器。`core/content.Registry` 将显式格式分派给已注册渲染器，不根据输入文本猜测语法。

渲染器消费 context 与完整源字符串，返回被动 `grid.Drawable` 和错误。有用内容可以伴随错误返回。应用决定是否展示准备失败的部分内容；忽略错误会抹掉真实失败事实。

## 准备完整快照

`markdown.NewRenderer(markdown.RendererConfig{Look: look})` 固定外观并返回中性的 `content.Renderer`。每次准备都渲染完整源。结果文档可以绘制和重排，但不暴露会修订已接受结果的语义 setter。

`SourceSnapshot.Prepare` 可作为 `program.Work[content.Prepared]` 执行。`StreamDocument.Accept` 验证来源身份、修订与 EOF 状态，迟到的工作线程不能覆盖新内容。自定义渲染器必须移交只读语义结果；布局缓存不授予修改源的权限。

## 组合可选渲染器

Markdown 解析最多接受 256 个同时打开的块，包含段落和列表项。结构由 Goldmark 拥有；超过边界时，在继续嵌套或递归遍历块之前返回 `ErrBlockNestingLimit`。代码围栏中的引用标记仍是普通正文。这是块嵌套预算，不代表对全部行内语法或所有解析成本的限制。被拒绝的解析不返回 drawable，已结束的 `StreamDocument` 会以准备错误报告 `Failed`。

Markdown 链接只允许 `http`、`https` 和 `mailto` 目标。地址形式的标签必须与目标指向同一规范化网站主机或完整邮箱收件人集合。校验使用文字渲染器的可见文本投影，因此被丢弃的控制字符不能掩盖待判断的地址。不同或歧义的标签不携带隐藏的点击目标；即使 `Look.Target` 使用零值样式，也会显示实际目标。

Markdown 表格在测量前，将单元格与配置的规则图案准备为独立文字字段。边缘结合字符与前置字符获得保留原样式和链接的空格基底，让补白与分隔符保有自己的列。每列除了可读下限，还为最宽的不可分割字素预留空间；这些下限无法同时容纳时，表格采用记录布局，不丢弃单元格内容。

Markdown 扩展钩子接收应用提供的被动渲染函数。`Look.SetRenderer` 只接收 `markdown.FencedCode` 和 `markdown.DisplayMath`：语法识别归 Markdown 所有，未知标识属于程序配置错误，会在改变已有注册之前 panic。传入 nil renderer 会移除对应的有效钩子；渲染失败仍通过 renderer 的 error 结果返回。这样代码围栏可以使用高亮、数学使用 LaTeX，同时不要求 Markdown 模块导入其同级模块。准备 Mermaid 输出涉及外部进程，应在绘制前作为作用域工作完成。

`latex.Render` 接收有深度上限的表达式正文，不接受数学模式分隔符或文档命令。解析器统一拥有所支持命令的参数、上下标和分组规则，所有不支持输入的诊断都经 `Formula.Err` 返回，渲染不会写 stdout 或 stderr。`08`、`1e`、`0x` 和引号等普通数学文字按表达式语法处理，不采用 Go 字面量规则。文字原子保留完整显示字素，因此组合 emoji 和结合符号在布局与绘制时使用相同几何。数学模式忽略空白；文本样式参数保留空白，包括百分号注释后的换行边界。这是面向终端的表达式子集，不是 TeX 文档引擎。

把一个组合字素拆到不同语法原子中，可能使终端实际列宽偏离数学布局，例如 `👩{‍💻}^2`。如果任意数学原子的列边界发生移动，`Formula.Err` 会报告不支持的几何，展示保留源码；整行总宽相同也不足以证明内部布局正确。同一个原子内的完整字素继续受到支持。`\exp` 等命名算子共用同一语法，不要求花括号参数，也不会把后面的上标当作参数消费。

终端原生图片仍是活动资源。复制其单元格矩形不构成永久图片发布协议：`grid.Capture` 对原生 painter 返回 `errors.ErrUnsupported`。应用可以显式选择文本最终表示。

Mermaid 的 Unix 适配器让启动进程保持可回收状态，直到进程组取消和最终终止操作完成，再回收启动进程并收束管道。它不等待其他进程回收已经终止的非直接子进程僵尸。`core/process` 独占共享的操作系统观察和信号边界；无法保证该身份生命周期的平台在构造时返回 `errors.ErrUnsupported`。主动离开 Unix 进程组的进程不在该边界内。

Windows 上的 Mermaid 和命令示例组合 `process.Job`。该能力独占进程创建时的作业归属、进程句柄观察、终止和清理。各消费者拥有已经准备的标准文件、输出复制和取消策略，并负责回收返回的启动进程、关闭作业。解析并发布使用这项新进程能力的适配器依赖前，应先发布更新后的 UI 模块。

返回的每个列表项 `Block` 将子内容和标记保存在一起。高度为零的扩展不会消耗标记；标记会出现在当前宽度下第一个可见子块旁边。整项不可见时，仍保留一行标记。`Doc.Len` 统计这些可独立保留的块，嵌套 `ExtensionError.Block` 指向返回序列中包含该错误的外层块。`Rows` 保留标记对应的列偏移，不把列表装饰加入可搜索或复制的正文。

## 如实表达复制能力

渲染行可提供 `text.Row` 软折行元数据，在不声称拥有通用 Markdown 源映射的情况下支持逻辑复制和重排。格式诊断属于准备阶段，解析器、网络或外部渲染器不会在 `Paint` 或 `HeightForWidth` 中执行。

每一版 Markdown blocks 拥有自己的宽度布局缓存。在 `Doc.SetBlocks` 前开始的读取使用当时的内容完成，后续读取看到替换后的版本。如果子块高度和间隔行的总和超过 int 范围，布局会在替换有效缓存前被拒绝。嵌入的 drawable 仍遵循其自身的并发约束。
